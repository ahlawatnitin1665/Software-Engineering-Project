# Week 2 : 401 for a freshly issued JWT

## Error:

A user could log in successfully, but every "protected"
request immediately returned `401 Unauthorized` -- even
with the token attached.

> POST /api/student/events 401
> { "success": false, "message": "Unauthorized: token
> expired or invalid" }

## Relevant Context

We had just introduced JWT authentication with an access
token and a refresh token:

+ login issues both tokens and stores the access token in
  `localStorage`
+ the axios request interceptor attaches
  `Authorization: Bearer <token>`
+ the auth middleware verifies with a shared secret

A freshly issued token was being rejected, so the problem
was in *verification*, not in issuing.

## Key Observation

The issue came from the fact that there were **two
different sources of the secret**.

The auth service read the secret from a config constant
that was baked in at module load, while the middleware
read it from `process.env.JWT_SECRET`.  In our run-scripts
(`npm run dev`), the `.env` file is loaded *after* some
modules have already loaded, so the two paths could
produce different values -- and a token signed with one
value is meaningless to a verifier using the other.

## Solution

Centralise configuration in a single module loaded very
early, and make it the only reader of environment
variables:

``` typescript
// config/env.ts
export const env = {
  jwtSecret: process.env.JWT_SECRET!,
  jwtExpiresIn: process.env.JWT_EXPIRES_IN!,
};
```

Both the auth service and the middleware `import { env }`
from that one place.  Tests also pin the same secret
explicitly in their setup.

``` typescript
// auth.middleware.ts
const decoded = jwt.verify(token, env.jwtSecret);
```

**Because** a token's validity is relative to the exact
secret (and clock) used to verify it; there must be
exactly one source of truth for that value.

## Files touched

+ `code/backend/src/config/env.ts` (new)
+ `code/backend/src/modules/auth/*` (login, refresh)
+ `code/backend/src/middleware/auth.middleware.ts`
+ `backend/tests/` (setup pins JWT secret)
